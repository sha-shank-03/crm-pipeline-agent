# Contribution and prior art

This project implements one complete local CRM maintenance workflow: investigate a stable opportunity ID, cite linked evidence, stage only a close-date/next-step correction, review an immutable digest, apply against exact record/evidence/account revisions and reconcile retry delivery to the original receipt. Java owns write authority and persistence; Python owns bounded investigation and orchestration.

CRM record/history APIs, conditional updates, human approval and idempotency are established techniques. [HubSpot deal APIs](https://developers.hubspot.com/docs/api-reference/legacy/crm/objects/deals/guide) and [LangGraph review/replay semantics](https://docs.langchain.com/oss/python/langgraph/interrupts) are prior-art references reviewed on 2026-10-08. No code or vendor dataset is copied from them. The motivating [Databricks sales data and agents posting](https://www.databricks.com/company/careers/engineering---pipeline/staff-software-engineer-sales-data--agents-8760171002) was reviewed on that date; it is context, not employer endorsement or evidence of meeting the role's seniority.

The authored contribution is an inspectable CRM-specific contract and evidence package: exact two-field semantics, conservative revision-based rejection, cached-result permission rechecks, transactionally consumed approval/receipt/history and independent pre-review/final-state checks. The benchmark includes distinct committed-close, meeting/negation, conflicting evidence, stable-ID/access and consistent/closed cases. Three isolated repetitions test deterministic reproducibility; they are not three independent datasets.

The latest-note baseline shares the grammar, Java authority and reviewer. Its M2 development error has valid literal provenance but lacks semantic support. The synthetic reviewer rejects it, leaving the final CRM correct while pre-review precision remains 2/3. This distinction is part of the evaluation contract. M3 retains the strict 32-outcome pre-review gate and zero unauthorized writes; no comparison advantage is required.

All data and labels are fictional and authored by the same author as the rules. The English extraction grammar is deliberately narrow. No enterprise identity, real CRM connector, human-review quality, external blind validation, live model performance, portable power-loss durability or business savings is established. M3 rules matched 32/32 unique held-out pre-review outcomes in each repetition; baseline matched 28/32. Its four wrong proposals have valid provenance but fail semantics and are rejected by the synthetic reviewer. These same-author examples illustrate the contract, not independent data or model quality. See `m3.md` and `../EVIDENCE.md` for measured M1/M2/M3 outcomes and unexecuted hosted/production work.
