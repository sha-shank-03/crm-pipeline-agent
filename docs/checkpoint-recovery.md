## Authored-v6 candidate

Checkpoint save writes strict UTF-8 JSON into one same-directory temporary, flushes and fsyncs it, closes it, then attempts the same os.replace. Only native Windows codes 5/32/33 receive up to three further attempts, with delays of 20, 50 and 100 milliseconds (four total attempts, 170 milliseconds of configured sleep). These delays are a bounded local policy, not a guarantee that a denial will clear. Other platforms and native errors propagate immediately. If a nonretryable error follows a transient one, that permanent error propagates. Exhaustion preserves the first denial with an attempt note.

The save function never deletes/truncates the existing target, rewrites it in place, changes the serialized value or creates another action key. Temporary cleanup runs on success/failure. A cleanup failure attaches a note to an existing primary error rather than replacing it; a retained temporary is disclosed and must not be mistaken for a committed checkpoint. Deterministic tests check unchanged old bytes on denied/exhausted replacement. At the initial source checkpoint, actual Windows denial/release checks were pending; all three later passed in worker and independent main runs.

The resume controller is unchanged. An intact pending apply is reconciled through operation_result with the original request ID and arguments. A found receipt ends recovery without apply/review/approval recreation. Only an authoritative not-found result can permit retry of the original apply, subject to the existing cancellation and budget checks. Missing pending intent requires operator reconciliation. A committed effect and failed local save must not be treated as a successful completed evaluation slot.

Fourteen new pure methods test each selected native denial, same fsynced temporary, the exact retry bound, first-error preservation, nonretryable/platform errors, secondary cleanup/serialization/fsync errors, failed first creation and no in-place fallback. Recovery doubles exercise a committed effect followed by exhausted final-checkpoint persistence, original-receipt query and repeated resume without another apply, transient final-save success, not-found query followed by only the original action, failed queries and save failure before authority dispatch. They simulate controller/key behavior; they do not replace Java policy integration. All 84 pure methods (70 existing plus 14 new) passed. Zero new business case-set runs, Java processes or HTTP servers executed for this correction.

Authored-v5 source/results/checkpoint were archived before edits.
